## Task 1: Auto-eaten in `inventory.js`

Today a past meal is consumed only when `m.ate` is an ISO string; `ate === false` means skipped; `ate === undefined` shows in `pending()` ("Did you eat these?") and is held back in `reserved()`.

- Add `function impliedAte(m, date, today)`: returns `m.ate` if it's a string; `null` if `m.ate === false`; `endOfDay(date)` (local 23:59:59.999 of `date`, as an ISO string) if `m.ate === undefined` and `compareDate(date, today) < 0`; otherwise `null`. Export it.
- `stock(inv, days, cat, now, staplesOn)`: use `impliedAte(m, date, toLocalDate(when))` instead of `m.ate`. Keep the existing `ateMs > nowTs` / `ateMs < startMs` guards.
- `reserved(...)`: a past meal (`d < today`) with `ate === undefined` is now consumed, so don't reserve it (the "past" branch only reserves meals with no implied ate, i.e. none). Bought meals on past days with `ate === undefined` are likewise consumed, not reserved. Today and future: unchanged.
- `pending(...)`: return `[]` always (kept for API compatibility); remove its callers in Task 3.
- Tests in `inventory.test.js`:
  - a past meal without `ate` consumes its ingredients at the end of its day;
  - a past meal with `ate: false` doesn't consume;
  - an explicit `ate` time is respected;
  - today's and future meals aren't consumed;
  - meals before the Kitchen `start` are ignored;
  - `reserved()` doesn't hold back past meals without `ate`;
  - update any existing tests whose expectations relied on past un-ate meals being reserved or pending (explain each change in the commit message).

## Task 2: Tabs, Week, hidden views

- `TABS = [["today","Today"],["week","Week"],["shop","Shop"],["meals","Meals"]]`. Add a `week` icon to `ICON` (a simple calendar SVG in the existing style). Tab grid becomes 4 columns.
- Rename the current `renderToday` to `renderWeek` (all of its content, as-is: day nav, week strip, Suggest my week, the day's meals editor, staples, Something else). Map `week: renderWeek`.
- Remove the "Did you eat these?" pending panel from it (auto-eaten), and the `pendate` / `pendskip` / `pendall` actions.
- Everything that sent the user to `today` for planning now goes to `week`: `applyPlan` (both branches), `suggestWeek`, `openday`, `addto`, cart `doAddMeal` if it switches tab, the Shop's day links, and any `state.tab="today"` that pairs with setting `state.date`. Grep `state.tab="today"` and decide each.
- **Hidden views** like Targets: `weigh` and `kitchen` stay in the render map but not in `TABS`. Generalise the Targets back logic: `state.tabBefore` + a shared `backBtn()`; actions `view` (`data-v` = `targets` | `weigh` | `kitchen`) and `back`. Keep `targets` / `targetback` working (or route them through `view` / `back`). Weigh-in and Kitchen views get a Back control in their header.
- Entry points: Shop gets a small link "At home" → `view kitchen` (near the Already-covered panel or the summary line). Weigh-in is reached from Today (Task 3).
- Stored or in-memory `state.tab` of `weigh` / `kitchen` on load falls back to `today` / `shop` (only `today`, `week`, `shop`, `meals` are valid start tabs).
- Kitchen copy that refers to "Ate it" / confirming meals: trim to match auto-eaten.

## Task 3: New Today and first run

`renderToday()` always shows the real today (`iso(new Date())`), independent of `state.date`.

- **First run** (spec): `settings.setupDone !== true` → setup card instead of the weigh-in box: phase chips (`data-act="mode"`), calories for that phase (`data-set="kcal.<mode>"`), protein (`data-set="protein"`), **Save** (`data-act="setupdone"`: sets `setupDone:true`, `saveSettings()`, shows "Plan my week →" (`data-act="tab" data-v="week"`)). In `initStore`, after loading: if `setupDone` is absent and there are any days or weights, set it `true` and `saveSettings()`.
- **Weigh-in box:** if no weight for today: "Morning weight [kg] Save" (reuse the Weigh-in save logic / action so validation and trend stay identical). If logged: one line "84.6 kg today · 7-day avg 84.2 ↓0.3" (use the existing trend helpers; omit the average part when there isn't enough data) as a button → `view weigh`.
- **Weekend not tracked:** "Weekend, eat how you like." plus the weigh-in box; a link "Plan today anyway →" goes to Week on today's date.
- **Nothing planned (weekday):** "Nothing planned. Plan my week →" (to Week).
- **Macros:** one compact block: "2434 / 2500 kcal" and "208 / 170 g protein" each with a thin bar (reuse `.bar`), no "left to spend" lines.
- **Staples:** the existing chip row (tap toggles today's skip, as now); no Edit or + here (those live on Week).
- **Meals:** one line each: slot, name, portion label (Light / Standard / Loaded), "Bought" tag if bought. Tap → sheet `today:<i>` with: Recipe (opens the recipe sheet), portion dial (`tier`), Swap, Remove (two taps). Use the existing actions with `date` = today so behaviour (fit, held, locks) is unchanged. No Ate it.
- **Ate something else?** link toggles the existing Something else form for today (same `extra` add path and "fit portions" behaviour).
- Today shows no day nav, no week strip, no Suggest buttons, no Clear unbought, no "+ breakfast" pickers.
- Escape every meal/catalogue string with `esc`.
