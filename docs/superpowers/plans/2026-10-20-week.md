Spec: `docs/superpowers/specs/2026-10-20-flow-redesign-design.md` ("Week (v0.23.0)"). Commit each task to `main` by explicit path (don't stage CRLF-only files); CI green before the next. Main file `apps/android/app/src/main/assets/weekday_fuel/Weekday_Fuel.html`.

## Task 1: Week screen

Replace today's `renderWeek` (the old planning view) with:

- **Header:** eyebrow "Week", h2 "Tue 20 – Sun 2" style range, and a ⋯ button opening a small page menu sheet `weekmenu`: **Use a plan** (opens the existing plan sheet), **Clear unbought meals** (existing two-tap action and copy), **Edit targets** (opens Targets).
- **Every day row:** eyebrow "Every day", the staples chips with their existing Edit and + (the staple sheet). Toggling a chip here is NOT a per-day skip; chips here only open Edit (tap) and + adds. Per-day skipping moves to the day menu.
- **Day tiles:** today through the end of next week (Mon–Sun), one tile per day: short weekday + date number, kcal (or "–"), coloured pip as now (on target / under / over; weekends "off" unless tracked). Tapping a tile scrolls to that day's block (or, for an untracked weekend, offers "Plan this weekend day" which sets `track` as today).
- **Tally:** "N of M planned days on target" (M = tracked days from today with meals; on target = the current pip rule "good"). Replace `weekStrip`'s kcal-sum sentence.
- **Empty (no meals on any tracked day from today on):** big **Plan my week** (`suggestweek`) and a small link "or use a plan: Fewest items" (opens the plan sheet). Same `wk.label` logic for what "week" means.
- **Days:** one block per day from today through the end of next week that is tracked (weekdays, or weekends with `track`). Untracked weekends show as a single muted line "Sat 24 · off · Plan it".
  - Block header: "Wed 21", kcal / target, protein, a "Fit portions" link when the day's pip isn't "good" and it has unlocked meals, and a ⋯ button → day menu sheet `daymenu:<date>`: **Re-suggest this day** (existing suggest-a-day for that date), **Skip a staple** (lists that day's staples as toggles; existing per-day skip), **Something else** (opens the existing extras form for that date inside the sheet), **Leave the day out of the cart** (existing `leaveout`, only when the day is in the cart and unbought meals exist).
  - Meals: one line each, as on Today (slot, name, portion, kcal, protein, "Bought" / "Not in cart" tags). Tap → meal sheet. Generalise Today's `today:<i>` sheet to `meal:<date>:<i>` with: Recipe, portion dial, Swap, **Leave out of cart / Put back in cart** (existing `mealshop`, shown when the date is today or later), Remove (two taps). Hide portion/Swap/Remove when locked (bought or past). Today's tab uses the same sheet with today's date.
  - Extras ("Something else" entries) listed as one line each with remove, as now.
  - **+ Add** at the end of the block → the existing add sheet (`add:` flow from the cart work) but with a meal picker first: open a sheet listing meals that fit the day's empty slots (reuse the old `+ breakfast` list logic), then on pick go straight to placing on that date (`place`/`apply` path, Replace / extra choice when the slot is full).
- **Past days** are not listed.
- All actions keep their current handlers where possible; set `data-d` on every per-day control so the click handler's date resolution picks the right day (don't rely on `state.date`).
- Remove from Week: day nav arrows, the old single-day editor, "Suggest a day" / "New suggestion" buttons, the "+ breakfast/lunch/dinner/snack" pickers, the dead `addto` action, "Meals share ingredients across the week." line.
- Notes (`weekNote`, `mealNote`, plan notes) render at the top of Week; keep the scroll-into-view behaviour.
- Escape every meal/catalogue/user string with `esc`.
