If an item has no source, stop and report it rather than guessing. Catalogue test: every counted-unit item has a positive `unitSize`.
2. Move `MACROS` out of the HTML into the pure layer if needed so `staples.js` can be tested (e.g. pass it in as an argument; don't duplicate the table).
3. New `staples.js` (`window.WeekdayFuelStaples`): `DEFAULTS`, `parse(list, cat)`, `onDay(staple, date, day)`, `forDay(staples, date, day)`, `macros(id, amount, cat, macros)`, `cost(id, amount, cat, store)`, `needs(staples, dates, daysMap)` → `{ id: total }` over the given dates. Exactly as the spec says. Load it in the HTML after `inventory.js`.
4. `catalogue.js` `shopList` / `coveredList` (shared need building): the second argument may be a number (old behaviour) or a `{ id: total }` map added to the item's need (alongside meal needs). Pin that a number gives identical output to today.
5. Tests: new `staples.test.js` (add to the CI list in `.github/workflows/release-android.yml`) and shop tests for the map form.

## Task 2: Kitchen and day totals

1. `inventory.js`: `stock()`, `reserved()`, `prune()` take `staplesOn(date)` → `[{ id, amount }]` instead of `fixtureOn(date, key)`. Uses happen at local midnight with the staple's amount; reserved from tomorrow to the day before the first shop day. Keep the 366-day cap. Update tests (existing Dare/Grenade cases expressed via the callback; add amount > 1 and a non-fixture staple).
2. `Weekday_Fuel.html`:
   - `S().staples` read through `WeekdayFuelStaples.parse(S().staples ?? DEFAULTS, CAT)` in one helper `staples()`.
   - `staplesOn(date)` helper = `forDay(staples(), date, dayOf(date))`; replace every `invFixtureOn` / fixture callback use.
   - `totals(day)` takes the date (find all callers) and adds staple macros and cost instead of the `settings.fixtures` loop.
   - `dayOf` stops writing default `fx`; `case "track"` no longer writes `fx` defaults (tracked weekends count as weekdays via `onDay`).
   - Shop: build the staple need map from shop days (`needs(staples(), shopDays(), state.days)`) and pass it wherever `fxDays()` was passed (`shopRows`, covered list, planner score/week cost, no-have list). Remove `fxDays`, the "Dare + Grenade for how many days?" stepper and its `fxdays` handler.
   - The planner's fit uses `totals`, so staple macros count automatically; check `suggestWeek` / `fitTiers` for any direct `settings.fixtures` use and replace it.
