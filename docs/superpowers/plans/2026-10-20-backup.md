Spec: `docs/superpowers/specs/2026-10-19-backup-design.md`. Commit each task straight to `main` (stage by explicit path), CI green before the next task. No local Android SDK: Kotlin is verified by CI (`:app:testDebugUnitTest :app:assembleDebug`).

Paths: assets `apps/android/app/src/main/assets/weekday_fuel/`, JS tests `apps/android/app/src/test/js/`, Kotlin `apps/android/app/src/main/java/dev/weekdayfuel/app/`, Kotlin tests `apps/android/app/src/test/java/dev/weekdayfuel/app/`.

## Task 1: `backup.js` (pure) and tests

- New `backup.js`, ES5 IIFE like `cartadd.js` (`module.exports` in Node, `root.WeekdayFuelBackup` in the page). Load it in `Weekday_Fuel.html` with the other module `<script src>` tags.
- Exports:
  - `PREFIX = "weekdayfuel."`, `EXCLUDE = ["weekdayfuel.v1.prices", "weekdayfuel.v1.colesPrices", "weekdayfuel.backup", "weekdayfuel.beforeRestore"]`.
  - `appKeys(storage)`: keys with the prefix, not excluded, sorted.
  - `build(storage, now, appVersion)` → pretty JSON string `{ app: "weekdayfuel", v: 1, exportedAt, appVersion, data }`. `now` is a Date.
  - `parse(text)` → `{ ok, backup }` / `{ ok: false, error }`. Error strings: "That file isn't JSON.", "That isn't a Weekday Fuel backup.", "This backup is from a newer version of the app. Update the app first.", "The backup's data is damaged." Keys outside the prefix and excluded keys are dropped silently; non-string values are an error.
  - `summary(backup)` → `{ exportedAt, appVersion, days, orders, weighIns, hasKitchen }` (days/weighIns from `JSON.parse(data["weekdayfuel.v1"])`'s `days`/`weights` object key counts; orders = array length of `weekdayfuel.v1.orders`; hasKitchen = `weekdayfuel.inventory` present). Any parse failure counts 0/false.
  - `summaryText(sum, fmtDate)` → "Backup from 12 Oct · v0.15.0 · 46 days, 9 orders, 30 weigh-ins, Kitchen stock" (omit zero parts except days; omit Kitchen when false; singular forms).
  - `restorePlan(storage, backup)` → `{ remove: [...], set: {...} }`: remove every `appKeys(storage)` key not in `backup.data`; set every backup key.
  - `applyPlan(storage, plan)` with `storage` `{ set(k,v), remove(k) }`; throws on the first failure.
- `backup.test.js` with a Map-backed fake storage: round trip (build → parse → data equal), exclusions, each parse error, `v: 2` refused, foreign keys dropped, summary on real-shaped data and on garbage, summaryText singulars, restorePlan removes stale keys and leaves excluded ones alone, applyPlan.
- Add `apps/android/app/src/test/js/backup.test.js` to the explicit list in `.github/workflows/release-android.yml:53`.

## Task 2: Android host

- New `backup/BackupMessages.kt` (`object BackupMessages`): `saved(name, at)`, `error(message, needNewFile)`, `opened(json, name)`, `info(name: String?)` → JSON strings with types `backupSaved`, `backupError`, `backupOpened`, `backupInfo`. Unit test `backup/BackupMessagesTest.kt` like `HostMessagesTest`.
- New `backup/BackupFiles.kt` (class taking a `Context`):
  - `rememberedUri(): Uri?` from `SharedPreferences("backup")` key `uri`, only if `contentResolver.persistedUriPermissions` still holds it with write permission.
  - `remember(uri)`: `takePersistableUriPermission(READ|WRITE)` (catch `SecurityException`), store it.
  - `displayName(uri): String?` via `OpenableColumns.DISPLAY_NAME`.
  - `write(uri, json)` with `openOutputStream(uri, "wt")`, UTF-8; `read(uri): String` capped at 10 MB (throw if bigger).
- `MainActivity`:
  - Fields: `pendingBackupJson: String?`, `backupFiles`, and launchers `createBackup = registerForActivityResult(CreateDocument("application/json"))` and `openBackup = registerForActivityResult(OpenDocument())`.
  - `onHostMessage` cases:
    - `backupSave`: `json` required (else `backupError` "Couldn't save the backup. Try again."). If `newFile` or no remembered URI → store pending, `createBackup.launch(name)`. Else write on `Dispatchers.IO` via `lifecycleScope`; success → `saved(displayName, nowIso)`; failure → `error("Couldn't update {name}. Save as a new file instead.", needNewFile = true)`.
    - `backupOpen`: `openBackup.launch(arrayOf("application/json", "*/*"))`.
    - `backupInfo`: reply `info(displayName(rememberedUri))`.
  - Create result: null URI → `error("", false)`; pending missing → error "Couldn't save the backup. Try again."; else remember, write on IO, reply saved / error.
  - Open result: null → `error("", false)`; else read on IO → `opened(json, displayName)` or `error("Couldn't read that file.", false)`.
  - Replies on the main thread through `replyToPage`. No new permissions in the manifest. No bridge changes: still only `APP_ORIGIN`.

## Task 3: Page

- `const BACKUP_KEY="weekdayfuel.backup", BEFORE_KEY="weekdayfuel.beforeRestore"`; `let restoring=false`. Guard `lsSave`, `queueWrite`, `lsSetTicks`, `lsSetSent`, `lsSetColesSent`, `lsSetSpecials`, `lsSetOrders`, `lsSetInv` and the price-cache writers with `if(restoring)return` (return `false` where callers expect a boolean).
- A storage adapter `lsAdapter={keys(){...localStorage keys},get:k=>localStorage.getItem(k),set:(k,v)=>localStorage.setItem(k,v),remove:k=>localStorage.removeItem(k)}`.
- `state.backup={busy:null|"saving"|"opening", error:null, needNewFile:false, remembered:null|name, pending:null|{backup,summary}}`.
- Targets view: Backup panel after the targets panel.
  - No host (`typeof WeekdayFuelHost==="undefined"`): "Backups need the Android app."
  - Last backup line from `BACKUP_KEY` (`fmtShort(at)`, days ago, `esc(name)`) or "No backup yet. Save one to Google Drive so you can restore it on a new phone."
  - Buttons: **Update backup** (only when `remembered`), **Save as a new file**, **Restore from a file**; disabled while busy with "Saving…" / "Opening…".
  - Error line (escaped) and, with `needNewFile`, the note to save as a new file.
  - Pending restore: summary text plus **Replace everything on this phone** (two taps via `state.armed="restore"`) and **Cancel**.
  - **Undo restore** (two taps, `state.armed="undorestore"`) when `BEFORE_KEY` exists.
- Opening Targets (both the `targets` action and `tab` with `targets`) posts `{type:"backupInfo"}`.
- Actions: `backupupdate` / `backupnew` → `backupSave` with `json: WeekdayFuelBackup.build(lsAdapter,new Date(),APP_VERSION)`, `name: "WeekdayFuel-backup-"+iso(new Date())+".json"`, `newFile`; `backupopen`; `restorego`; `restorecancel`; `undorestore`.
  - `APP_VERSION`: read from an existing version constant if the page has one; otherwise `"unknown"`, which is fine.
- Host message handler (in the existing `WeekdayFuelHost.addEventListener("message")`): `backupInfo` → `remembered`; `backupSaved` → write `BACKUP_KEY` `{name,at}`, remove `BEFORE_KEY`, `remembered=name`; `backupError` → `error=message||null`, `needNewFile`; `backupOpened` → `parse`; ok → `pending`; else `error`. Always clear `busy`; render if on Targets.
- Restore (`restorego`, armed): `const cur=WeekdayFuelBackup.build(lsAdapter,new Date(),APP_VERSION)`; try `localStorage.setItem(BEFORE_KEY,cur)` else show "Couldn't keep a copy of your current data, so nothing was changed." Then `restoring=true`; try `applyPlan(lsAdapter, restorePlan(lsAdapter, pending.backup))`; on throw, apply the `cur` backup's plan back, `restoring=false`, show "Restore failed; your data was put back."; on success `location.reload()`.
- Undo: parse `BEFORE_KEY`, same apply path with `restoring=true`, then remove `BEFORE_KEY` and reload.
- Escape the file name and every backup-derived string with `esc`.
- Browser check (no host): the panel shows the Android-only line, and nothing throws. Optionally stub `window.WeekdayFuelHost` in the console to walk save/open/restore, using a backup built from the current storage.
