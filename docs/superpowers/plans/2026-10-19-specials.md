# Specials Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When an approved swap for Dare or Grenade is on special and works out cheaper at the chosen store, the Shop row offers it with Use it / Keep buttons. A chosen swap flows into totals, both trolleys, the saved order and stock-in (stocked as the main item).

**Architecture:**
- **Data:** the approved swaps go on the `dare` and `grenade` catalogue items as `swaps` (data only). Each swap store product has `size: serves`, so the existing quantity × size maths works unchanged.
- **Logic:** a new pure module `specials.js` (`window.WeekdayFuelSpecials`) does four things:
  - collects the swap ids to price;
  - applies live prices to swaps;
  - suggests the best swap for a row;
  - rewrites a row's store line to the chosen swap.
- **HTML:** `Weekday_Fuel.html` wires it into price refresh, `buildCat`, the shop rows, the product lookups, the fingerprint and the next-shop reset.

Spec: `docs/superpowers/specs/2026-10-19-specials-design.md`. The spec uses the field name `swaps`, not `alts`.

**Tech Stack:** Vanilla JS (ES5 in modules), node:test.

## Global Constraints

- **Git:** commit straight to `main`, staging by explicit path. Never stage `.superpowers/`. Never `git stash`, `git clean` or `git reset --hard`.
- **Store pages:** Woolworths and Coles pages never get a JS bridge, and no Kotlin changes are needed. Nothing in CI talks to the real stores.
- **Escaping:** escape every catalogue- and swap-derived string in HTML with `esc`.
- **Storage:**
  - Existing localStorage keys keep their shape; additive optional fields are OK.
  - The new key is `weekdayfuel.v1.specials`.
  - The new settings field is `mutedAlts: ["itemId:swapId"]`, additive through `deepMerge`.
- **Swap ids:**
  - Coles ids must be 4–7 digits (Kotlin `ColesPricesJson.parseIds` rejects the whole list otherwise).
  - Woolworths stockcodes are positive integers.
- **Never swap automatically.** A swap is used only after the user taps "Use it".
- **Nutrition guard:** per serve, `swap.per.p >= main.per.p - 5` and `swap.per.k <= main.per.k + 80`. Day totals keep the main item's macros, so no macro code changes.
- **Version:** bump only in Task 4.
- **Checks:**
  - Tests: `node --test "apps/android/app/src/test/js/*.test.js"`.
  - Parse check: extract the last inline `<script>` of `Weekday_Fuel.html` to `%TEMP%/wf.js` and run `node --check`.

### Task 2: `specials.js` pure module and tests

**Files:**
- Create: `apps/android/app/src/main/assets/weekday_fuel/specials.js`
- Create: `apps/android/app/src/test/js/specials.test.js`
- Modify: `.github/workflows/release-android.yml:53`, appending ` apps/android/app/src/test/js/specials.test.js`.

**Interfaces:**
- Consumes the `colesId(product)` function, which the callers pass in. In tests, use `require("../../main/assets/weekday_fuel/catalogue.js").colesId`.
- Produces `WeekdayFuelSpecials` (`module.exports` in node):
  - `swapIds(items, colesId)` returns `{stockcodes:number[], colesIds:string[]}`: every swap's Woolworths stockcode and Coles id.
  - `applySwapPrices(items, wPrices, cPrices, colesId)` returns new items.
    - For each swap store product with a live entry, it sets `price` (when > 0), `was` (only when > price, else null), `special: !!live.special`, `available: live.available !== false` and `live: true`.
    - Items without swaps, or without live data, are returned as the same object.
    - Inputs are not mutated.
  - `passesGuard(main, swap)` returns `boolean`.
  - `suggest(row, item, store, muted)` returns `{swap, product, quantity, cost, saving, dk, dp} | null`.
    - `muted` is a Set or array of `"itemId:swapId"`.
    - The remaining need in serves is `Math.max(0, row.need - (row.have || 0))`.
    - The main cost is `row[store].cost`. If there is no main line, the main cost is Infinity, so any special swap is cheaper.
    - Candidates are swaps with `swap[store]` where `special === true` and `available !== false`, that aren't muted and that pass the guard.
    - For each candidate: `quantity = Math.ceil(remaining / swap.serves)` and `cost = round2(quantity * product.price)`. Only candidates with `cost < mainCost` qualify.
    - The cheapest wins, with ties going to the first listed.
    - `saving = round2(mainCost - cost)`, or `null` when there's no main line. `dk = swap.per.k - item.per.k` and `dp = round1(swap.per.p - item.per.p)`.
    - It returns `null` when the remaining need is ≤ 0.
  - `useSwap(row, store, s)` returns a new row whose `row[store]` is `{product: s.product, quantity: s.quantity, cost: s.cost, buy: s.quantity + " × " + s.swap.name, swap: s.swap.id}`. The input row isn't mutated.
  - `applyChoices(rows, items, store, choices, muted)` returns `{rows, used:{[itemId]: swapId}}`.
    - For each row whose item has `choices[row.id].use === swapId`, it calls `suggest`, restricted to that swap.
    - If that swap still qualifies (special, available, guard, cheaper), it applies `useSwap` and records `used`.
    - Otherwise the row is unchanged.
    - A muted swap still applies if chosen: muting only stops suggestions.

const wp = (code, price, extra = {}) => ({ name: "W" + code, url: "https://www.woolworths.com.au/shop/productdetails/" + code, stockcode: code, size: 1, price, ...extra });
const cp = (id, price, extra = {}) => ({ name: "C" + id, url: "https://www.coles.com.au/product/x-" + id, size: 1, price, ...extra });

const row = (need, have, wCost, cCost) => ({ id: "dare", need, have, woolies: wCost == null ? null : { product: wp(72280, 4.65), quantity: need - (have || 0), cost: wCost, buy: "x" }, coles: cCost == null ? null : { product: cp(8991361, 4.65), quantity: need - (have || 0), cost: cCost, buy: "x" } });
